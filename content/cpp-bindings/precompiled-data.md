# 미리 컴파일된 스크립트 사용
## 기능
일반적으로 엔진이 시작되면 Angelscript 플러그인은 프로젝트의 스크립트 폴더에 있는 모든 `.as` 파일을 읽고 파싱한 뒤 컴파일합니다. 특히 CPU와 하드 드라이브가 느린 플랫폼에서는 이 작업에 비교적 오랜 시간이 걸릴 수 있습니다.

패키징된 빌드의 시작 시간을 단축하기 위해 패키징된 바이너리가 미리 컴파일된 스크립트 캐시를 생성하도록 할 수 있습니다. 미리 컴파일된 스크립트 캐시 파일이 있으면 플러그인은 모든 스크립트 파일을 불러오고 파싱하고 컴파일하는 대신, 캐시에서 컴파일된 스크립트 바이트코드를 직접 불러옵니다.

또한 플러그인은 스크립트의 Angelscript 바이트코드와 동일하게 동작하는 C++ 코드 파일 디렉터리를 생성할 수 있습니다. 이 C++ 파일을 포함해 게임 바이너리를 다시 컴파일하면 Angelscript의 JIT 컴파일 시스템과 연결되어 가상 머신의 바이트코드 실행을 네이티브 C++로 대체합니다. 이를 통해 스크립트 코드의 런타임 실행 속도가 크게 향상됩니다.

## 사용법
미리 컴파일된 스크립트는 이를 불러올 `.exe` 바이너리와 동일한 바이너리에서 생성해야 합니다.

생성 방법은 다음과 같습니다.

- 실행할 구성으로 게임을 패키징합니다.
- `-as-generate-precompiled-data` 명령줄 매개변수를 지정해 `ProjectName.exe`를 실행합니다.

그러면 게임 배포에 포함해야 하는 `ProjectName/Script/PrecompiledScript.Cache` 파일이 생성됩니다.

다음에 패키징된 게임을 실행하면 `.as` 스크립트 대신 미리 컴파일된 캐시에서 스크립트를 불러옵니다.

## 트랜스파일된 C++ 코드
생성 단계에서는 캐시뿐 아니라 컴파일된 각 스크립트 파일에 대응하는 파일이 들어 있는 `AS_JITTED_CODE/` 폴더도 출력합니다.

이 폴더를 프로젝트의 소스 폴더로 복사한 다음 적절한 구성으로 게임의 `.exe`를 다시 빌드할 수 있습니다.

프로젝트에 `AS_JITTED_CODE/` 폴더를 포함할 때는 해당 폴더가 포함되는 모듈의 프로젝트 `Build.cs` 파일에서 `AngelscriptCode`를 종속성으로 지정해야 합니다.

`AS_JITTED_CODE/`를 포함해 컴파일한 새 `.exe`와 `PrecompiledScript.Cache` 파일을 함께 사용하면 Angelscript를 실행할 때 플러그인이 알맞게 최적화된 C++ 코드를 자동으로 실행합니다.

## 호환성
미리 컴파일된 스크립트에는 C++ 프로퍼티의 하드코딩된 바이트 오프셋과 C++ 구조체 크기가 직접 포함됩니다. 따라서 현재 실행 중인 바이너리와 다른 바이너리에서 생성한 `PrecompiledScript.Cache` 파일은 절대 사용하면 안 됩니다.

게임의 패키징된 `.exe`를 다시 빌드할 때마다 해당 `.exe`에서 미리 컴파일된 스크립트 캐시를 **항상** 다시 생성하세요.
(물론 생성된 C++ 코드를 바이너리에 추가하기 위한 재빌드는 예외입니다.)

반대의 경우에는 필요하지 않습니다. 게임 바이너리를 다시 컴파일하지 않고도 `.as` 스크립트 파일을 변경하고 새 `PrecompiledScript.Cache`를 생성할 수 있습니다.
이전 바이너리에 생성된 C++ 코드가 포함되어 있었다면 새 캐시와 더 이상 일치하지 않으므로, 새 `AS_JITTED_CODE`로 바이너리를 다시 빌드할 때까지 사용되지 않습니다.

## 스크립트 다시 불러오기
`PrecompiledScript.Cache` 파일을 사용하면 스크립트 폴더의 실제 `.as` 파일을 불러오지 않습니다. 따라서 해당 파일의 변경 사항이 적용되지 않으며 핫 리로드도 비활성화됩니다.

미리 컴파일된 스크립트가 있어도 이를 불러오지 않으려면 패키징된 게임 바이너리에 `-as-development-mode` 명령줄 매개변수를 전달하세요.
